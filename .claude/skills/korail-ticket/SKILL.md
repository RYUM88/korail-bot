# 코레일 명절 승차권 예매 대행

`korail-holiday-ticket/` 도구를 대신 실행한다. 모든 명령은 그 폴더 안에서 돈다.

## 먼저 확인할 것

**이 세션이 `bt.korail.com` 에 닿는가.** 클라우드(Claude Code on the web)에서는 조직
이그레스 정책으로 막혀 있어 예매를 실행할 수 없다. 다음으로 확인한다.

```bash
curl -sS -I -m 15 https://bt.korail.com/holiday/main | head -1
```

403 이나 연결 거부가 나오면 **여기서는 실행할 수 없다**고 사용자에게 바로 알린다.
사용자 PC 의 Claude Code 나 터미널에서 `./yemae.sh` 로 돌려야 한다고 안내한다.
막힌 것을 우회하려 하지 말고, 되는 척도 하지 않는다.

## 예매 시각은 반드시 확인받는다

`--at` 이 틀리면 나머지가 다 소용없다. 사용자가 시각을 주지 않았으면 **추측하지 말고
물어본다.** 코레일 공지의 예매 시작 시각을 그대로 받는다.
상대 시각(`+30s`)은 리허설에만 쓴다.

## 순서

### 1. 준비 상태 확인

```bash
cd korail-holiday-ticket && ls .venv/.korail-ready 2>/dev/null || echo "준비 안 됨"
```

준비가 안 됐으면 `./yemae.sh clock` 을 한 번 돌린다. 실행기가 가상환경·라이브러리·
브라우저를 알아서 깐다(몇 분 걸리므로 백그라운드로 돌리고 사용자에게 알린다).

### 2. 로그인 (예매일 전에 한 번)

```bash
./yemae.sh login
```

브라우저가 열린다. 사용자가 로그인하고 창을 닫으면 프로필에 저장된다.
이 명령은 사용자가 창을 닫을 때까지 안 끝나므로 **백그라운드로 실행**하고,
"브라우저에서 로그인한 뒤 창을 닫아 주세요" 라고 안내한다.

### 3. 셀렉터 확보 (예매일 전에 한 번)

```bash
./yemae.sh probe --out candidates.json
```

출력에서 최고점 후보의 `cssPath` 를 확인하고, 사용자에게 **그게 진짜 예매 버튼이
맞는지 브라우저의 빨간 테두리로 확인해 달라고** 요청한다. 확인되면 그 값을
`my-config.json` 의 `selector` 에 저장한다.

예매 기간이 아니어서 후보가 없을 수 있다. 그건 정상이니 그대로 알리고,
셀렉터 없이 자동 탐색으로 가도 된다고 설명한다.

### 4. 리허설

```bash
./yemae.sh "+30s" --dry-run
```

실제로 누르지 않고 대상만 표시한다. 실전 전에 한 번은 돌린다.

### 5. 실전

```bash
./yemae.sh "2026-09-15 14:00:00"
```

- 목표 시각까지 계속 돌므로 **반드시 백그라운드로 실행**한다.
- 30분 전쯤 띄우는 것이 좋다. 그보다 훨씬 이르면 그냥 기다린다고 알린다.
- 클릭 후에는 브라우저가 열린 채 사용자를 기다린다. **좌석 선택과 결제는
  사용자가 직접 해야 한다**고 분명히 말한다.
- 끝나면 출력의 `클릭 성공` / `타이머 오차` / `클릭 시각`을 사용자에게 전한다.
  실패했으면 실패했다고 그대로 말한다.

## 설정 저장

반복 실행할 값은 `korail-holiday-ticket/my-config.json` 에 굳힌다
(`config.example.json` 참고). 이 파일이 있으면 실행기가 자동으로 읽는다.

```json
{
  "at": "2026-09-15 14:00:00",
  "selector": "#btnReserve",
  "login_pause": false
}
```

## 하지 않을 것

- 로그인 정보를 대신 입력하지 않는다. 사용자가 브라우저에서 직접 한다.
- 예매 시각을 임의로 정하지 않는다. 모르면 묻는다.
- `.profile/` 은 로그인 세션이 든 폴더다. 커밋하거나 내용을 읽지 않는다.
- 성공 여부를 부풀리지 않는다. 버튼을 눌렀다고 표가 잡힌 것은 아니다.
