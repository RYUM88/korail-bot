# 코레일 명절 승차권 예매 버튼 자동 클릭

`https://bt.korail.com/holiday/main` 의 명절 승차권 **예매 버튼을 지정한 시각에 눌러 주는**
도구입니다. 시각 기준은 내 PC 시계가 아니라 **코레일 서버 시계**입니다.

```
[1/5] 코레일 서버 시각을 확인합니다
  서버 시각 동기화: 2026-09-15 13:59:12.031 KST  |  오프셋 +43714ms (±57ms, RTT 5ms, 표본 12/12)

[2/5] 목표 시각
  코레일 서버 기준 : 2026-09-15 14:00:00.000 KST
  내 PC 시계 기준  : 2026-09-15 13:59:16.286 KST
  남은 시간        : 00:00:47
...
[5/5] 클릭!
  발사 시각(서버 기준) : 2026-09-15 14:00:00.000 KST
  타이머 오차          : +0.3ms
  ✔ 클릭 성공 (real, 시도 2회)
    대상        : '추석 승차권 예매'
```

## 이 도구가 하는 일 / 하지 않는 일

**합니다**

- 코레일 서버 시계와 내 PC 시계의 차이를 밀리초 단위로 계산
- 예매 페이지를 미리 열어 두고, 예매 시작 시각에 예매 버튼을 클릭
- 버튼이 아직 안 열렸으면 정해진 시간 동안 재시도

**하지 않습니다**

- 로그인, 좌석 선택, 결제 — 브라우저를 열어 둔 채로 넘겨 드리니 **직접 이어서** 하세요
- 자동 로그인, 캡차 우회, 계정 여러 개 돌리기, 서버에 요청 퍼붓기

버튼 하나를 정확한 순간에 대신 눌러 주는 것이 전부입니다. 그 뒤는 사람이 합니다.

## 가장 쉬운 방법 — 한 줄 실행기

```bash
./yemae.sh "2026-09-15 14:00:00"      # macOS / Linux
yemae.bat "2026-09-15 14:00:00"       # 윈도우 (더블클릭해도 됩니다)
```

처음 실행하면 가상환경·라이브러리·브라우저를 알아서 준비합니다(몇 분 걸립니다).
그다음부터는 바로 뜹니다.

```bash
./yemae.sh clock                      # 서버 시각 차이 확인
./yemae.sh login                      # 미리 로그인해 두기
./yemae.sh probe                      # 예매 버튼 셀렉터 확인
./yemae.sh "+30s" --dry-run           # 리허설
./yemae.sh                            # my-config.json 설정대로 실행
```

## Claude 에게 시키기

저장소 루트에 `.claude/skills/korail-ticket/` 스킬이 들어 있습니다. **내 PC 에서**
Claude Code 를 켜고 말로 시키면 됩니다.

```
추석 예매 걸어줘. 9월 15일 오후 2시야
코레일 서버 시간 좀 확인해줘
예매 리허설 한번 돌려봐
```

Claude 가 준비 상태를 확인하고, 로그인·셀렉터 확인을 안내한 뒤, 목표 시각까지
백그라운드로 대기시켰다가 결과를 알려 줍니다.

> **클라우드(Claude Code on the web) 세션에서는 안 됩니다.** `bt.korail.com` 이
> 조직 이그레스 정책으로 막혀 있고 로그인 세션도 없습니다. 반드시 내 PC 에서
> 돌려야 합니다.

## 직접 설치해서 쓰기

실행기를 쓰지 않고 손으로 하려면:

```bash
pip install -r requirements.txt
playwright install chromium
```

파이썬 3.9 이상이 필요합니다. 이후 명령은 모두 이 폴더 안에서 실행합니다.

## 사용법

### 1단계 — 서버 시각 확인 (아무 때나)

내 PC 시계가 코레일 서버와 얼마나 어긋나 있는지 봅니다.

```bash
python -m korail_bot clock
```

```
[1/1] 코레일 서버 시각 : 2026-09-15 13:22:41.518 KST
          내 PC 시계     : 2026-09-15 13:22:39.106 KST
          차이           : 오프셋 +2412ms (±48ms, RTT 63ms, 표본 12/12)
```

내 PC 가 2.4초 느립니다. 이 도구는 이 차이를 자동으로 보정하므로 PC 시계를 맞출
필요는 없습니다.

### 2단계 — 로그인 (예매일 전에, 한 번)

```bash
python -m korail_bot login
```

브라우저가 열립니다. 코레일에 로그인한 뒤 **창을 닫으면** 저장됩니다. 로그인 상태는
`.profile/` 에 남아 이후 실행이 그대로 이어받으므로, 예매 당일에 로그인하느라
시간을 쓰지 않아도 됩니다.

### 3단계 — 예매 버튼 셀렉터 확인 (예매일 전에, 한 번)

**이 단계를 꼭 하세요.** 페이지 구조는 명절마다 바뀔 수 있습니다.

```bash
python -m korail_bot probe --out candidates.json
```

브라우저가 열리고 클릭 후보들이 점수 순으로 출력됩니다.

```
클릭 후보 3개 (점수 높은 순):

  [1] frame: https://bt.korail.com/holiday/main
      score= 106.9  <a> '추석 승차권 예매'
        css : #btnReserve
        id  : btnReserve   href: /booking/main
        on  : None
```

실제로 눌릴 요소는 브라우저에서 **빨간 테두리**로 표시됩니다. 그게 진짜 예매 버튼이
맞는지 눈으로 확인하고, 출력된 `--selector` 값을 실전에서 그대로 씁니다.

> 예매 기간이 아니면 버튼이 아예 없을 수 있습니다. 그럴 땐 예매 시작 직전에 다시
> `probe` 를 돌리거나, 셀렉터 없이 자동 탐색에 맡기세요.

### 4단계 — 리허설

진짜처럼 돌리되 클릭만 하지 않습니다. 30초 뒤로 목표를 잡아 보세요.

```bash
python -m korail_bot run --at "+30s" --dry-run
```

목표 시각에 "눌렸을 대상"이 빨간 테두리로 표시됩니다. 여기서 엉뚱한 것이 잡히면
`--selector` 로 직접 지정하세요.

### 5단계 — 실전

```bash
python -m korail_bot run \
  --at "2026-09-15 14:00:00" \
  --selector "#btnReserve"
```

- `--at` 은 **코레일 서버 시각** 기준입니다. 코레일 공지의 예매 시작 시각을 그대로 넣으세요.
- 목표 30분 전쯤 실행해 두는 것을 권합니다.
- 클릭이 끝나면 브라우저를 열어 둔 채 기다립니다. 창을 닫으면 종료됩니다.

## 자주 쓰는 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--at` | 설정 파일에서도 지정 가능 | 목표 시각. `2026-09-15 14:00:00` / `14:00` / `+90s` |
| `--selector` | 자동 탐색 | 클릭할 요소의 CSS/XPath. **지정을 권장** |
| `--lead` | `0ms` | 목표보다 이만큼 먼저 클릭 (네트워크 지연 보정용) |
| `--click-mode` | `auto` | `auto`/`real` 은 실제 마우스 이벤트(확실, ~130ms), `dom` 은 `el.click()` 직접 호출(~60ms 더 빠름) |
| `--reload-lead` | `3s` | 클릭 이 시간 전에 페이지 새로고침. `0` 이면 안 함 |
| `--reload-after` | `1s` | 버튼을 못 찾은 채 이만큼 지나면 새로고침 |
| `--retry-window` | `20s` | 클릭 재시도 총 제한 시간 |
| `--min-score` | `60` | 자동 탐색으로 클릭할 최소 점수 |
| `--dry-run` | 꺼짐 | 실제로 누르지 않고 대상만 표시 |
| `--keep-open-timeout` | `3600` | 브라우저가 닫히기를 기다리는 최대 시간(초) |
| `--headless` | 꺼짐 | 창 없이 실행 |

전체 목록은 `python -m korail_bot run --help`.

설정을 파일로 굳혀 두려면 `config.example.json` 을 복사해서 쓰세요.

```bash
cp config.example.json my-config.json   # 값을 수정
python -m korail_bot --config my-config.json run
```

`my-config.json` 이라는 이름으로 두면 `yemae.sh` / `yemae.bat` 가 자동으로 읽습니다.
`at` 과 `selector` 를 여기 넣어 두면 실행할 때 아무것도 안 붙여도 됩니다.

명령줄에서 직접 준 값이 설정 파일보다 항상 우선합니다.

## 서버 시각은 어떻게 맞추나

HTTP 응답의 `Date` 헤더를 읽습니다. 그런데 이 헤더는 **초 단위로 잘려** 있어서
한 번 읽으면 최대 1초가 틀립니다. 그래서 표본 하나를 값이 아니라 **구간 제약**으로 다룹니다.

요청을 `t0` 에 보내 `t1` 에 응답을 받았고 헤더가 `D` 라면, 서버가 응답을 만든 순간의
서버 시각은 `[D, D+1)` 안에, 그때의 내 시각은 `[t0, t1]` 안에 있습니다. 따라서

```
offset = 서버시각 - 내시각  ∈  [D - t1,  D + 1 - t0)
```

표본 12개를 0.12초 간격으로 모아 이 구간들을 교집합하면, 1초 경계 여기저기에
표본이 흩어지면서 폭이 왕복지연 수준까지 좁혀집니다. 캐시된 응답이나 순간적인
지연 폭증으로 표본 하나가 오염돼도 **가장 많은 구간이 겹치는 영역**을 고르는 방식이라
결과가 망가지지 않습니다.

테스트에서 실제로 43.7초 어긋난 서버를 **오차 17ms** 로 복원합니다.

한번 맞춘 뒤의 카운트다운은 전부 `time.monotonic()` 위에서 돕니다. 대기 도중 OS 가
NTP 로 시스템 시계를 보정해도 흔들리지 않습니다. 목표에 가까워질수록 (10분 · 5분 ·
2분 · 1분 · 30초 · 15초 전) 다시 맞추고, 마지막 8초는 네트워크를 건드리지 않습니다.

동기화 1회에 나가는 요청은 `HEAD` 12개이고, 연결 하나를 재사용합니다.

## 왜 엉뚱한 버튼을 안 누르나

자동 탐색은 '예매'가 들어간 것을 아무거나 누르지 않습니다.

- `예매확인` `예매취소` `조회` `환불` `안내` `공지` 가 들어간 라벨은 **제외**합니다.
  예매 버튼 바로 옆의 '예매 안내' 링크를 잘못 누르면 그날 기회를 날리기 때문입니다.
- 키워드가 라벨에서 차지하는 비중을 점수에 반영합니다. 라벨이 `승차권 예매`인 버튼이
  `예매 안내` 같은 링크를 크게 앞섭니다.
- 점수가 `--min-score` 미만이면 **아무것도 누르지 않습니다.** 애매한 것을 누르느니
  누르지 않는 편이 낫습니다.
- iframe 안까지 뒤지고, 프레임 전체에서 최고점을 고릅니다.
- 비활성(`disabled`) 상태의 버튼은 열릴 때까지 기다립니다.

그래도 가장 확실한 것은 `probe` 로 확인한 `--selector` 를 직접 넘기는 것입니다.

## 알아 두실 것

- 실행 전 코레일 공지에서 **예매 시작 시각**을 꼭 확인하세요. `--at` 이 틀리면 아무 소용이 없습니다.
- 유선 인터넷과 안정적인 전원을 권합니다. 절전 모드로 들어가면 대기가 깨집니다.
- 예매 버튼을 눌렀다고 표가 잡히는 것은 아닙니다. 이후 대기열·좌석 선택·결제는 직접 하셔야 합니다.
- 개인이 본인 표를 예매하는 용도로 만들었습니다. 코레일 이용약관과 정상적인 이용 범위를
  지키는 책임은 사용하는 분에게 있습니다.
